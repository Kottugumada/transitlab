What is TransitLab?

TransitLab is a data pipeline and vetting interface that re-runs transit searches on NASA's Kepler archive. It downloads real stellar brightness measurements, searches them for periodic dips consistent with a planet passing in front of its star, and ranks each candidate using a machine-learning classifier trained on the NASA Exoplanet Archive.

Everything here is based on a re-analysis of publicly available data, not new observations. The pipeline is designed to be fully reproducible, $0-cost (GitHub Actions + Neon free-tier Postgres + Render free-tier hosting), and honest about what it can and cannot claim.

Important: Every result is a candidate signal for human vetting. TransitLab never labels anything a "discovered planet." Even high-scoring detections require follow-up spectroscopy, centroid checks, and independent confirmation before any claim is valid.

Step 1 — Catalogue sync

The NASA Exoplanet Archive's TAP service is queried for all Kepler Objects of Interest (KOIs) with disposition CONFIRMED. This gives us the archive-measured period, transit depth, stellar parameters, and model SNR for each system — the ground truth we validate against.

Step 2 — Fetch light curve

For each target, all available Kepler long-cadence (29.4 min) quarters are downloaded from MAST via Lightkurve, stitched together, and cached locally. The full 4-year Kepler baseline gives ~1461 days of photometry per star.

Step 3 — Clean & detrend

Quality-flagged cadences are removed. A Savitzky-Golay filter (window ≈ 2 days) removes instrumental systematics and stellar variability while preserving transit-timescale signals.

Step 4 — BLS period search

Box Least Squares (BLS) scans a uniform frequency grid from 0.75 d to 50 d using 2000 trial periods. The best-fit box gives period, epoch, duration, depth, and SNR. When BLS locks onto a harmonic of the true period (a common aliasing effect), the pipeline detects the alias relationship and corrects the stored period back to the true value.

Step 5 — Score & store

An honest-features classifier (scikit-learn HistGradientBoosting, 13 catalogue features) trained on KOI dispositions assigns each detection a planet-likelihood score 0–1. "Honest" means it uses only features measurable from the archive catalogue — no features derived from the light curve itself — which eliminates leakage across the train/test split. The Detection record (period, epoch, depth, SNR, fold data, score) is written to Postgres.

The data

All data is from NASA public archives. No new observations are made.

NASA Exoplanet Archive

Kepler Object of Interest (KOI) table via TAP. Provides archive periods, transit depths, stellar parameters, and confirmed/false-positive dispositions. ~2500 confirmed KOIs in the current sync.

MAST / Lightkurve

Kepler long-cadence SAP and PDCSAP flux time series from the Mikulski Archive for Space Telescopes. Data spans 2009–2013 (Kepler primary mission). Up to 17 quarters per star.

Confirmed Planets Table

NASA Exoplanet Archive confirmed planets catalogue, used to populate the Backyard Tonight scheduler with verified host names, orbital periods, and transit durations.

No proprietary data

TransitLab v1 uses only public archival data. The photometry/ directory is intentionally absent — user-supplied observations are a v1.5 feature.

How to use this site

Candidates — explore the hunt results

The Candidates table shows every transit detection from the most recent BLS hunt run, sorted by classifier score (high = more planet-like).

  1. Use the score column to prioritize — scores above ~0.8 have good BLS SNR and catalogue-consistent features.
  2. Click any row to open the full vetting page, which shows the phase-folded light curve, secondary eclipse check, odd/even depth comparison, and the trapezoidal fit.
  3. The "Period" column shows the corrected period (after alias resolution), so a system found at P/2 by BLS will display its true period.
  4. Filtering by depth is useful: signals shallower than ~1000 ppm are harder to distinguish from systematics at this stage.
Explorer — look up any Kepler planet

The Explorer lets you fetch and fold the real Kepler light curve for any confirmed planet by name or KIC number.

  1. Enter a KOI name (e.g. K00001.01), Kepler planet name (e.g. Kepler-1b), or KIC ID.
  2. The archive period and epoch are used to fold the full 4-year light curve. What you see is real data, not a model.
  3. Use it to understand what a good transit detection looks like — sharp ingress/egress, flat bottom, symmetric shape, no secondary eclipse.
Backyard Tonight — plan an observation

Shows transits from confirmed exoplanet systems that are geometrically observable tonight from the configured location (default: Morgan Hill, CA).

  1. Rows are ranked by transit depth × host brightness — deeper transits around brighter stars are easier to detect with amateur equipment.
  2. The start/end/mid times are in local time. Mid-transit is the best time to be on-target for a photometric time series.
  3. Filter by minimum depth (ppm) to focus on targets detectable with your aperture. A 6″ telescope can typically reach ~3000 ppm on V<11 stars.
  4. These are geometrically predicted times — always cross-check against ETD or ExoClock before committing to an observation run.

Release notes

v1.0November 2025
  • Initial public release. Full pipeline: catalogue sync → BLS hunt on 50 confirmed Kepler hosts → honest-features ML scoring → three vetting tools.
  • Validation — Gate 1 (known-system recovery): PASS 72% (36/50 recovered). Recovery by period band: P<3d 79%, 3–10d 79%, 10–30d 62%, >30d 25%. Remaining misses are non-harmonic BLS aliases and long-period targets with <3 transits in the search grid.
  • Validation — Gate 2 (synthetic injection): PASS 95% (19/20 recovered). False-positive rate on quiet light curves: 0/10 = 0%.
  • BLS alias correction: when BLS locks onto a harmonic (P/2 through P/6), the pipeline now stores the corrected true period in the database, so the Candidates page shows meaningful values rather than raw aliases.
  • Period search grid: 0.75 d–50 d, 2000 frequencies. Lower bound raised from 0.5 d to avoid P/6 sub-harmonic floor traps at 1.5 d, 3.0 d, etc.
  • Honest-features classifier: HistGradientBoosting trained on 13 NASA Archive catalogue features. Stars split by KIC ID (never by row) to prevent leakage. No features derived from the fetched light curve, ensuring the score reflects archival knowledge rather than the BLS result itself.
  • Architecture: GitHub Actions batch, Neon Postgres free tier, Render free-tier web service. Running cost: $0/month.
v1.5 (planned)
  • User-supplied photometry (photometry/ directory support): ingest FITS or CSV time series from an amateur telescope for local BLS analysis.
  • TESS sector support: extend the hunt to TESS 2-min cadence data via MAST.
  • Centroid shift vetting: flag detections whose centroid moves during transit (EB contamination indicator).
